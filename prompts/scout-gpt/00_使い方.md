# YOUTRUSTスカウトGPT　使い方

**一度だけ準備すれば、次からはスプレッドシートのURLを貼るだけ**で、候補者全員の除外チェック・求人との相性判定・1通目のスカウト文作成・xlsx納品までを行います。

このGPTは、次の2つを1つにまとめたものです。

- **YOUTRUSTスカウト生成プロンプト v2**（除外ルール・判定・メッセージ設計・xlsx納品）
- **スカウト相性チェッカー**（「この人がこの求人の書類選考を通過する見込みがあるか」をA〜Dで判定）

判定の基準は「応募要件を満たすか」ではなく、「同じ求人に応募してくる他の人と比べたとき、この人が選ばれる理由があるか」です。要件を満たしているだけの求人は「C（決め手なし）」になり、スカウトは作りません。

---

## 1. 最初に一度だけやること

### 1-1 カスタムGPTを作る
1. ChatGPTの「GPTを探す」→「作成する」→「構成」タブを開く
2. **指示（Instructions）** に `01_GPT指示文.txt` の中身をすべて貼る
3. **知識（Knowledge）** に `02_統合ルール集.md` をアップロードする
4. **機能** で「ウェブ検索」と「コードインタープリターとデータ分析」をオンにする（スプレッドシート・URL・PDFを読み、xlsxを作るため）
5. 使える場合は Googleドライブ連携もオンにする（非公開のスプレッドシートや求人PDFを読みやすくなる）
6. 名前を「YOUTRUSTスカウトGPT」などにして保存する。**共有範囲は社内のみ**にする

> カスタムGPTが使えない場合は、ChatGPTの「プロジェクト」を作り、プロジェクトの指示に `01_GPT指示文.txt`、ファイルに `02_統合ルール集.md` を入れても同じように動きます。

### 1-2 スプレッドシートを作る
Googleスプレッドシートを1つ作り、シートを2枚用意します（`テンプレート_候補者.csv` と `テンプレート_求人.csv` をそれぞれ読み込むと早いです）。

**「候補者」シート**

| 候補者URL | リスト日付 | 媒体 | 紹介予定ポジション | メモ | 1通目送信日 | 1通目使用求人 | 2通目送信日 |
|---|---|---|---|---|---|---|---|
| https://youtrust.jp/... | 2026-09-25 | | | | | | |

- **必須は「候補者URL」だけ**です。他の列は空欄でかまいません
- 「1通目送信日」以降の列は、リマインド（2通目）を作るときに使います

**「求人」シート**（手持ち求人の一覧）

| 求人名 | 求人URL | 想定年収 | メモ |
|---|---|---|---|
| A社_BIアプリケーションエンジニア | https://drive.google.com/... | | |

- 求人票のURL（Googleドライブ上のPDFでも可）を入れておくと、GPTが中身を読んで判定します
- 募集が終わった求人は、メモに「募集停止」と書けば使われません
- 「求人」シートがない場合は、GPTのナレッジに入れた求人票 → マスターフォルダの順に探します

**共有設定**：スプレッドシート（と求人PDF）を「リンクを知っている全員が閲覧可」にしてください。GPTが開けないと、そこで止まって共有設定の変更をお願いします。社外に出したくない場合は、Googleドライブ連携を使うか、xlsx／CSVを直接添付してください。

## 2. 毎回やること

### 1通目を作る
1. 「候補者」シートに今日集めた候補者URLを貼る（1回20〜30名が目安）
2. GPTを開き、**スプレッドシートのURLだけを貼って送る**

```
https://docs.google.com/spreadsheets/d/xxxxxxxx/edit#gid=0
```

これだけで、除外チェック → 相性判定 → 1通目の作成 → xlsx納品まで進みます。途中で「開始してよいですか」とは聞かれません。今日の日付は自動で入ります（出力の冒頭に「基準日」として表示されます）。

### 2通目（リマインド）を作る
1. 1通目を送り終えたら、「候補者」シートの「1通目送信日」「1通目使用求人」を記入する
2. GPTに次のように送る

```
リマインド
https://docs.google.com/spreadsheets/d/xxxxxxxx/edit#gid=0
```

### 3通目（追加フォロー）を作る
「2通目送信日」を記入し、「3通目」＋URLを送ります。

### 長くて途中で止まったとき
「続けて」と送ると、残りを同じxlsxに追記します。

## 3. 結果の読み方

xlsxには次のシートが入っています。

| シート | 中身 |
|---|---|
| 1通目 | 候補者ごとの判定と、そのまま送れる完成メッセージ |
| 求人判定詳細 | 候補者×求人ごとのQ1〜Q4の判定と、求人票・プロフィールの原文引用 |
| 集計 | 判定の内訳、NG理由、送信実績 |
| 運用メモ | 運用のコツ |

### 最終判定

| 判定 | 意味 | どうするか |
|---|---|---|
| ◎ | 求人判定Aで、固有名詞2つ以上の掛け算でWhy youが書けている | ほぼそのまま送る |
| ○ | 求人判定Aだが情報がやや薄い、または求人判定Bで決め手を1行で言える | 1箇所直してから送る |
| ⚠（要リサーチ） | プロフィールが薄い・読めない | 送らない。追加で調べる |
| ⚠要判断 | 求人なし・情報交換候補（市場価値S）、または年収帯の合う求人なし | 送るかどうかを自分で決める。送るなら「〇〇の候補者は求人なしパターンで作って」と依頼 |
| NG | 除外ルールに該当、または求人判定C・D | 送らない |

### 求人判定（A〜D）

| 判定 | 意味 |
|---|---|
| **A 提案する** | 要件を満たし、この人ならではの強み（edge）が求人の必須要件に当たる |
| **B 条件付き** | 要件は満たすが、強みが当たるのは歓迎要件や業務内容まで |
| **C 決め手なし** | 要件は満たすが、他の応募者も持っているものしかない |
| **D 見送り** | 要件・職種・レベルのいずれかが合わない |

**判定Aでも、送る前に一度だけ「求人判定詳細」シートでGPTが引用した必須要件の原文を読んでください（10秒で済みます）。** GPTは単語が同じだけで一致と判断することがあります（例：「Oracle EBS」はERP製品で、Oracleデータベースの経験とは別物）。ルール集で防いでいますが、最後は人の目で確かめるのが一番確実です。

送信ボタン・予約ボタンは必ず自分で押してください。

## 4. 個人情報のルール（必ず守る）

- ChatGPTの設定で、**入力内容をモデルの学習に使わない設定**にする（設定 → データコントロール →「すべての人のためにモデルを改善する」をオフ。会社のTeam／Enterpriseプランは最初からオフ）
- GPTの共有範囲は社内のみにする
- 出力には候補者の氏名・連絡先は書かれず、YT番号で管理されます。スカウト文に**年齢や求人の年齢上限は書かないでください**
- 職務経歴書のテキストやPDFを直接貼る場合は、氏名・電話番号・メールアドレス・生年月日・住所の番地・顔写真を伏せてから貼ってください。社名から個人が特定できそうなら「SES企業A社」のように伏せてください
- 社内の選考情報（どの会社に何人推薦して何人通ったか、見送り理由など）はシートやチャットに入れないでください

---

## 5. 判定がおかしいと思ったら

「この判定は違う」と思った例があれば、候補者の属性（氏名は不要）・求人・GPTの判定・あなたの見立てを中川までお送りください。`02_統合ルール集.md` に反映して、GPTのナレッジを差し替えます。

パートナー企業（株式会社ルートのような対象外企業）が増えた場合も、ルール集の3章に追記してナレッジを差し替えてください。
